# 2026-10-01: What stands between Leech and a first release

For the next agent. Leech is **not releasable** as of 2026-10-01 (commit ac00031). The browser works as a daily
driver for its owner; what is missing is everything needed to hand it to someone else. Read
[conventions.md](../conventions.md), the newest hand-off and this plan before starting. Commit and push per
finished step (allowed in this repo), never with AI attribution.

"Released" here means: a `v0.3.0` GitHub Release with a tarball of a release build, an AUR package that installs
it, and a fresh user on Arch getting a working browser (pages, sign-ins, extensions, DRM video) without a
checkout or a Chromium build of their own.

Marks: **[checked]** was looked at in the source or the build; **[to check]** is expected but nobody has verified it.

## Blockers, in order

### 1. A release build

- Today `out/Leech` is a component build (`is_component_build = true` in `chromium/args.gn`, 8.1 GB): hundreds
  of `.so` files, not something to ship. **[checked]**
- Add `chromium/args-release.gn` next to `args.gn`: `is_component_build = false`, `is_debug = false`,
  `symbol_level = 0`, `dcheck_always_on = false`, the codecs and fontconfig lines from `args.gn`, plus the Widevine
  line from step 4. Keep `is_official_build = false` unless PGO profiles are fetched (`chrome_pgo_phase = 0`
  stays); try `is_official_build = true` only as a later optimisation.
- Build into its own folder: `gn gen out/Release` with those args, `autoninja -C out/Release chrome -j 5`.
  This is a full build: hours, many GB. Tell the owner before starting, keep it at a third of the cores and
  lowest priority (conventions), check free memory first. The disk has room (about 600 GB free on 2026-10-01).
- Done when: `out/Release/chrome` starts with `LEECH_UI_DIR=<repo>/ui` and `npm run check:ui -- --chromium` passes
  against it (`LEECH_CHROMIUM=<src>/out/Release npm run check:ui -- --chromium`).
- Done 2026-10-01: built from `chromium/args-release.gn` (with Widevine) in 4 h 20 min at `-j 5`; `chrome` is
  498 MB, `out/Release` 9.9 GB. All 22 scenarios pass against it.

### 2. The UI next to the binary, not in the checkout

- The UI is read from disk at run time: `LEECH_UI_DIR`, else `<dir of chrome>/leech-ui`
  (`UIFolder()` in `chromium/leech/leech_ui.cc`, marked `ponytail:` for grit later). **[checked]**
- The lazy route is enough for a release: ship `ui/` as `leech-ui/` beside the binary and let the launcher stop
  setting `LEECH_UI_DIR` when it runs an installed copy. Packing the UI into the binary with grit can wait.
- The page script (`ui/guest/`) is read from the same folder (`GuestScript::Load`), so it travels along.
- Done when: an installed tree without the repo starts, draws the UI, and the page script works (the
  `page-script` scenario against it).
- Done 2026-10-01 with step 3: `tools/stage.mjs` puts `ui/` beside the binary as `leech-ui/`; `check:ui` leaves
  `LEECH_UI_DIR` unset when the binary has a `leech-ui/` beside it, and all 22 scenarios pass on the staged tree.

### 3. A launcher and file layout for an installed copy

- `data/leech` assumes the repo in `~/Projekte/Apps/leech` and the build in `~/Projekte/Apps/leech-chromium/...`
  (`LEECH_HOME`, `LEECH_CHROMIUM`), copies Electron-era JSON once, and logs to `~/.local/state/leech`. **[checked]**
- Pick the installed layout (suggested: `/usr/lib/leech/` with `chrome`, its `.pak`/`icudtl.dat`/snapshot files,
  `locales/`, `chrome_sandbox`, `chrome_crashpad_handler`, `leech-ui/`; `/usr/bin/leech` as the launcher). Which
  files a Chromium install needs: `chrome/installer/linux/common/installer.py` and its staging lists in the
  checkout. **[to check]**
- Make the launcher work in both cases: prefer an installed `/usr/lib/leech/chrome` when it exists, the checkout
  otherwise. Keep `--user-data-dir=$XDG_DATA_HOME/leech/chromium` and `--class=dev.mikaeww.Leech` (the desktop
  file's `StartupWMClass`).
- Sandbox: Chromium on Linux needs either unprivileged user namespaces or a setuid `chrome_sandbox`. Arch has user
  namespaces; decide whether the package ships the setuid helper. Check `chrome://sandbox` in the installed copy.
  **[to check]**
- Done 2026-10-01: `node tools/stage.mjs <src>/out/Release <prefix>` lays out `<prefix>/bin/leech`,
  `<prefix>/lib/leech/` (binaries stripped, 498 to 333 MB for `chrome`; the files from installer.py's lists that
  this build has, `locales/*.pak`, `leech-ui/`) and the desktop file, icon and license under `<prefix>/share`:
  429 MB in all. The launcher runs `../lib/leech/chrome` beside itself when it exists, so the same script serves
  `/usr/bin/leech` and a checkout's `~/.local/bin/leech`. No setuid helper: the staged launcher, started in a
  private Xvfb with throwaway XDG folders, drew `chrome://leech` without `LEECH_UI_DIR`, and `chrome://sandbox`
  said "adequately sandboxed" (namespace sandbox, seccomp-BPF). **[checked]**

### 4. Widevine (DRM video)

- An unbranded build has `enable_widevine = false` (`third_party/widevine/cdm/widevine.gni`). With
  `enable_widevine = true` the library CDM component is on for Linux (`enable_widevine_cdm_component`), so
  Chromium's component updater should fetch the CDM itself; it is never bundled (`bundle_widevine_cdm` needs Chrome
  branding). **[checked in the .gni files; the download itself is to check]**
- If the component updater doesn't deliver it in an unbranded build, the fallback Arch's own Chromium users take
  is copying `WidevineCdm/` from an installed Google Chrome next to the binary; the AUR package can do that as an
  optional step. Leech never redistributes the CDM.
- Done when: `chrome://components` lists the Widevine CDM with a version, and a DRM test stream (for example
  Bitmovin's DRM demo) and Netflix play in the release build.
- The README claims "DRM ... behave like in Chrome": true only after this step.

### 5. Google API keys

- The build has no Google API keys (`google_api_key` unset). Without them Chromium can't use Safe Browsing
  lists, Translate, network geolocation or sync, and shows a "Google API keys are missing" infobar, which Leech's
  layout hides. Signing in to Google *websites* is unaffected. **[to check, one by one]**
- The owner decides: get own keys (Google's "Chromium API keys" process; they go into `args-release.gn` or the
  `GOOGLE_API_KEY`/`GOOGLE_DEFAULT_CLIENT_ID`/`GOOGLE_DEFAULT_CLIENT_SECRET` environment), or ship without and say so.
- If without: Settings › Privacy offers Safe Browsing (`ui/panels/settings/chromium.js`). A switch that does
  nothing is a lie; hide it or say it needs keys.
- Decided 2026-10-01: ship without keys. The Safe Browsing line is gone from Settings › Privacy (the pref stays at
  Chromium's default); the README has to say which Google services are missing. Translate is still offered:
  whether it works without keys is **[to check]** in the release build.

### 6. The package and the release

- AUR: a `leech-bin` package from the GitHub Release tarball (building Chromium in `makepkg` would take users
  hours). Its PKGBUILD installs the step-3 layout, the desktop file, the icon (`assets/leech-light.png` as
  `dev.mikaeww.Leech`), the launcher and the licenses (Leech's `LICENSE` with Office Commun's copyright, and
  Chromium's credits from `about:credits` / the build's `LICENSE` files). Dependencies: what `ldd out/Release/chrome`
  lists beyond glibc (gtk3, nss, alsa-lib, libcups, libxkbcommon, mesa, ...). **[to check]**
- Version: `package.json` says 0.2.0; About shows Chromium's version (`version_info` in `LeechHandler::BootInfo`).
  Decide what About shows (suggested: "Leech 0.3.0 · Chromium 154.0.8037.57").
- GitHub Release `v0.3.0`: the tarball, its sha256, release notes from the roadmap's phases 9 to 12. Only on the
  owner's go.
- README: replace "There is no release or package yet" with the AUR install; fix the feature list for the Chromium
  build (passwords and import are Chromium's own there, not libsecret and Leech's importers); keep Building for
  people who want their own build.

## Release check (before tagging)

On the release build, installed from the package into a clean system user or a throwaway `XDG_DATA_HOME`:

- `npm run check` and `npm run check:ui -- --chromium` against the release binary: all pass.
- First run shows the welcome; every page works (`welcome-pages`).
- Real sites: Google search and sign-in, YouTube, a Widevine stream, a Chrome Web Store extension installed and
  its popup from the extension door, a saved and filled password, a download, a PDF.
- Native Wayland on Hyprland (`--ozone-platform=wayland`), and X11.
- Start time and memory against the current build, written down, not guessed.

## Not blocking

Middle-button autoscroll, the swipe disc, the shield in private windows, popups from a peeked page, the Electron
shell's focus gap. They stay in the roadmap.
